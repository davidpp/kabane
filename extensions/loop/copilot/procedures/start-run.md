---
title: STARTING A LOOP RUN
---
The loop extension, installed at {{extension}}, drives an issue to done through a coding harness, in a detached runner: run `kabane loop start <id>` in your shell from your working directory, the project's checkout, as the kabane command KABANE ON THIS MACHINE names. An issue with no subtasks runs as a single issue, and a parent runs its subtasks. Read `kabane loop --help` for the flags (`--implementer` picks claude, codex or gemini) and pass only what the human asked for: the loop's settings (kabane_configGet key loop) supply the rest. When the human tells you to run an issue ("run JCAB-79 with codex"), that is the go-ahead: run the command once. When a run is your own suggestion, name the issue and the harness and wait for a yes. If the command refuses (the loop extension is not enabled, the issue already has a run or nothing to do, this directory is not its scope), report its message as it is and do not retry with other flags. When it starts, report the run id it prints, where the run works, and how to follow and stop it: the run's tab on the board, `kabane loop status <runId>`, and `kabane loop stop <runId>`. The run's sessions change the code, not you, and a question one of them asks is the human's to answer.
